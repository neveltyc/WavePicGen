# 06 · 路线图、风险与待定决策

> 目的：给出**引擎优先（engine-first）**的分阶段路线、风险与缓解、以及**需要维护者拍板的关键决策**。
> 两份独立方案在「先做扎实的核心引擎 + CLI，GUI 作为其可视化外壳」上完全一致——这是风险最低、复用最高、可维护性最好的推进顺序。

---

## 1. 推进总策略：引擎优先

> 「引擎和 CLI 一旦正确，GUI 只是它的可视化外壳」——把风险与价值最大化的部分（L2 核心）前置。

先把 **`model + parser + layout + svggen + export(resvg)` + CLI** 做正确、可测、可复现；
GUI 在其上叠加，外壳可替换（R1/R3 共享 L2）。这与 §04 的分层、单向依赖、Reuse Map 一脉相承。

---

## 2. 里程碑

| 阶段 | 目标 | 交付物 | 验收 |
| --- | --- | --- | --- |
| **P0 引擎内核** | 文档模型 + 布局 + SVG 生成 + resvg 栅格化 + CLI 雏形 | `core` 库 + `cli`：吃 JSON/DSL → 出 SVG/PNG/JPEG | CLI 能把示例文档渲染为像素一致的 SVG/PNG |
| **P1 格式 / DSL / 兼容** | 定稿文档模型；实现 DSL（WaveJSON 超集）双向解析；**WaveJSON 导入** | parser + schema + 示例集 | 能导入 WaveDrom 图；文本 ⇄ 模型无损往返；视觉回归快照建立 |
| **P2 GUI 只读预览** | Tauri 外壳 + SVG 显示 + 文本面板**双向同步** + 导出按钮 | 可运行 GUI（Win/Linux） | 改文本→实时重绘；能导出 PNG/JPEG/SVG |
| **P3 交互编辑（MVP）** | 画布选择/拖拽/边沿编辑/栅格吸附 + 撤销重做 + 命令面板 | 鼠标可编辑波形 | 对标 TimeGen 基础交互；三向往返成立 |
| **P4 手册级特性** | 亚周期/异步边沿、关系箭头（setup/hold/delay）、测量标尺、无效区、皮肤、PDF 导出 | 手册级标注能力 | 能复刻一张真实手册时序图至「可直接采用」 |
| **P5 打磨与分发** | 撤销/重做完善、性能、安装包、文档、CI 矩阵、（加分）tikz/EPS 导出 | Windows + Linux 安装包 | 两平台一键安装运行；CI 出 release |

> **最小可用闭环**在 P2 末（能看/能改文本/能导出）；**对标 WaveDrom 的产品价值**在 P1 末（CLI 批渲染 + 导入）就已具备。

---

## 3. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Tauri 在 Linux 的 WebView（WebKitGTK）显示与 Windows（WebView2）不一致 | 屏幕预览细节差异 | **导出统一走 resvg**，出图不受 WebView 影响；预览级差异可接受；必要时切 Electron |
| Rust 学习/构建成本（若引擎用 Rust） | 团队上手变慢 | 引擎用 Rust、外壳用熟悉的 Web；或先 TS 核心后下沉 Rust（见 D3） |
| **亚周期边沿 + 关系标注的布局复杂度** | layout 是自研难点 | 作为 P4 核心攻关；P0 先支持周期对齐，渐进引入实数坐标 |
| resvg 不支持 SVG 动画/部分滤镜 | 仅静态子集可用 | 时序图本就是静态矢量，无影响 |
| 字体跨平台不一致 | 出图字形差异 | **打捆字体**；导出可 outline/内嵌 |
| Qt 的 LGPL 合规 / PySide 打包（若走 R3） | 合规与分发成本 | 走动态链接满足 LGPL；Tauri 路线无此问题 |
| 过度设计 / 范围蔓延 | 拖慢交付 | 严守「引擎优先 + 非目标清单（见 01 §6）」；按里程碑切片 |

## 4. ⭐ 待定决策（请维护者拍板）

这些决策不阻塞「继续完善文档」，但**决定动手时的第一行代码**。建议逐条确认：

| 决策 | 选项 | 倾向 / 建议 |
| --- | --- | --- |
| **D1 实现路线** | (a) Web/Tauri（首选） · (b) Qt/PySide6（强力备选） · (c) Electron · (d) 其它 | 取决于**团队主力技能**；若无强约束 → **(a)**，最契合可维护/复用/跨平台 |
| **D2 开源 vs 闭源/商业** | (a) 开源 · (b) 闭源/商业 | 影响 Qt(LGPL/商业) 选择；若开源 → R1 生态最干净 |
| **D3 核心引擎语言**（若选 R1） | (a) Rust 核心 + WASM（可复现最强） · (b) TS 核心（最快出活） · (c) 先 TS 后 Rust | 看重「手册级可复现/性能」→(a)；看重「尽快出活」→(c) 渐进 |
| **D4 导出格式优先级** | SVG+PNG+JPEG 为 MVP；PDF/EPS/tikz 排序 | 建议 MVP = SVG+PNG+JPEG，PDF 紧随；EPS/tikz 作加分 |
| **D5 团队技能画像** | Web/TS · Rust · Python/C++ · .NET | 直接影响 D1/D3，请补充 |

> 我已在文档中给出**带理由的建议默认值**；维护者确认或调整后，即可据此把「初步方案」收敛为「实施计划」。
