# 01 · 需求与范围

> 本文档把维护者提出的目标拆解为可评审、可验证的需求项，并界定本项目的范围与非目标。
> 这是后续所有技术决策的依据。

## 1. 一句话愿景

打造一个**严肃 / 学术 / 手册级**的数字电路时序图绘制工具：产出的图形要达到可直接放进
**教科书、芯片数据手册（datasheet）、规格书、学术论文**的质量，而不仅仅是「能看」的草图。

「手册级（manual-quality）」具体意味着：

- 排版与字体可控、清晰、可嵌入（矢量文字而非位图文字）；
- 线宽、网格、对齐、间距遵循一致的排版规则，细节经得起放大；
- 输出为**矢量图**，在论文/手册中无限缩放不失真；
- 输出**确定性强、可复现**（同一份描述始终得到逐像素一致的图，便于版本管理与 CI 出图）。

## 2. 功能需求（来自维护者原始描述）

| 编号 | 需求 | 说明 / 验收要点 |
| --- | --- | --- |
| FR-1 | **GUI 图形界面** | 提供可视化的编辑窗口，所见即所得地查看/修改时序图。 |
| FR-2 | **GUI 内的命令 / 文本输入** | 在界面中通过文本（DSL/脚本）或命令面板驱动绘图，与可视化编辑**双向同步**。 |
| FR-3 | **可编辑的波形描述格式** | 以纯文本格式持久化文档；人类可读、可手写、可被脚本生成、可进 Git diff。 |
| FR-4 | **位图导出：PNG、JPEG（至少）** | 可设置分辨率/DPI、背景透明（PNG）。 |
| FR-5 | **矢量导出：SVG 优先，最好含 PDF 等** | SVG 为首要矢量格式；PDF/EPS 为加分项（论文/手册常用）。 |
| FR-6 | **跨平台：Windows + Linux (amd64)** | 两个平台均需可安装、可运行、产物一致。 |
| FR-7 | **实现形态：原生或网页渲染均可** | 维护者明确接受原生实现，或基于网页渲染的桌面应用。 |
| FR-8 | **可参考 WaveDrom / TimeGen 的设计与逻辑** | 借鉴其文档格式与交互范式，但不被其局限（见 02 调研）。 |

## 3. 由愿景推导出的隐含需求

这些没有被显式提出，但「手册级 / 学术级」目标必然要求：

| 编号 | 需求 | 理由 |
| --- | --- | --- |
| IR-1 | **精确的排版与对齐引擎** | 手册质量的核心在布局规则，而非绘图框架本身。 |
| IR-2 | **确定性、可复现的渲染** | 同一文档在 GUI、CLI、CI 中产出一致；利于版本管理与回归测试。 |
| IR-3 | **无头（headless）渲染/导出能力（CLI）** | 学术/工程场景常需批量、脚本化、在 CI 中出图（参考 WaveDrom CLI）。FR-2 的「命令输入」与之同源。 |
| IR-4 | **GUI ↔ 文本 双向往返（round-trip）无损** | FR-2 + FR-3 的必然结果：可视化改动要能写回文本，反之亦然。 |
| IR-5 | **字体嵌入 / 文字转路径** | 保证导出件在他人机器/印刷流程中字形一致。 |
| IR-6 | **撤销/重做、复制粘贴、对齐吸附等基础编辑体验** | 严肃工具的基本盘。 |
| IR-7 | **复用既有成熟库优先（reuse-first）** | 商品化的难点（栅格化、编辑器组件、桌面外壳）尽量用成熟轮子并按需魔改，自研只投在差异化核心，提升可维护性、降低风险。 |

## 4. 时序图领域的内容需求（要能画出什么）

参考既有工具与真实手册中的时序图，至少应支持：

- **亚周期 / 异步边沿（实数时间坐标）【关键差异点】**：跳变可落在任意实数时刻（如 2.75 周期、17.3 ns），而非只能对齐周期边界。这是相对 WaveDrom 的关键增强，也是手册级异步/延迟时序的刚需。
- **时钟（clock）**：正/负边沿、带箭头边沿、占空比、分频/周期、相位偏移。
- **逻辑电平信号**：0 / 1 / 高阻 z / 弱上拉下拉 / 未知 x。
- **总线 / 数据（bus / data）**：多位数据段、带标签的数据块、变化点的「交叉」过渡。
- **信号分组（group）**：层级化分组与组标签。
- **间隔 / 折断（gap / spacer）**：表示时间压缩或省略。
- **边沿/时序关系标注（edge / arrow）**：建立时间（setup）、保持时间（hold）、传播延迟（tCO/tPD）、因果箭头与文字标签——这些**时序关系/参数是模型中的一等对象**（参考 TimeGen / TimingDesigner），而非事后绘制的装饰。
- **刻度与时间轴（ticks / time axis）**：周期编号、时间标注、表头/表尾文字。
- **注释与测量**：文本框、辅助线、区间标注、setup/hold 等参数标注。
- **（加分）模拟/类比波形**：阶梯、容性充放电、斜坡、亚稳态等（参考 undulate）。

> 详细的语义与语法草案见 [`05-waveform-format-draft.md`](05-waveform-format-draft.md)。

## 5. 非功能需求

- **性能**：常见规模（数十信号 × 数百周期）下编辑流畅、导出秒级。
- **可维护性（重点）**：**高内聚、低耦合**——渲染引擎与 GUI 彻底解耦，模块边界清晰、依赖单向；优先**复用成熟库并按需魔改**而非重复造轮子，自研面收敛到差异化核心（布局/格式）。详见 [`04-architecture-proposal.md`](04-architecture-proposal.md)。
- **可测试性**：核心引擎可在无 GUI 环境单元测试 + 视觉回归测试（SVG 快照对比）。
- **可分发**：每个平台提供单一安装包/可执行文件，依赖自包含。
- **可扩展性**：未来可加入皮肤/主题、新波形类型、新导出格式（如 LaTeX/tikz）。
- **国际化**：界面与图中文字支持中英文（CJK 字体）。

## 6. 明确的非目标（本项目不做什么）

界定边界，避免范围蔓延：

- **不做逻辑分析仪 / 信号采集**（那是 sigrok/PulseView 的领域）：本工具是**作图/创作**工具，不是测量/抓取工具。
- **不做电路仿真 / 波形仿真求值**：不从 RTL/Verilog 仿真生成波形（虽然未来可作为导入插件）。
- **不做原理图（schematic）绘制**：聚焦时序图这一种图。
- **初期不追求移动端 / Web 在线版**：先打好桌面端（Win/Linux）地基；架构上为未来 Web 版留口子。
- **初期不追求 macOS**：架构上保持可移植，但不作为首批交付目标。

## 7. 成功标准（验收）

1. 在 Windows 与 Linux(amd64) 上均能安装并运行 GUI。
2. 能用文本 DSL 与可视化编辑两种方式创建同一张时序图，并双向同步。
3. 能导出 PNG、JPEG、SVG（PDF 为加分项），矢量件在放大与印刷下清晰、文字可嵌入。
4. 能复刻一张真实手册中的代表性时序图（含时钟、总线、setup/hold 箭头标注），效果达到「可直接采用」的水平。
5. 提供命令行批量出图能力（无头引擎）。
